Пузыри

Введение

Пузыри появились для решения задачи получения отображения молекулы в виде графа. Это бывает необходимо для различных целей. Например, для получения описания молекулы в формате SMILES. Или для вычисления систематического названия соединения.

Существуют такие описания, для которых это можно сделать без особых проблем. Например:

H-C-C-O-H; H|#2|H; H|#3|H
или
/\\|`//`\`|`\\`/||\//

Но есть и такие, в которых это сделать невозможно без применения специальных алгоритмов:

C2H5OH
или
(HO)2P(O)–P(O)(OH)2

В традиционных химических формулах есть множество неоднозначностей. Например, скобки могут использоваться для описания разных ситуаций:

CH3$color(brown)(CH2)2$color()OH --> CH3-$color(brown)CH2-CH2$color()-OH
$color(brown)(CH3)2$color()O --> $color(brown)CH3$color()-O-$color(brown)CH3

Но здесь хотя бы можно их формально отличить при помощи подсчёта валентностей. Однако, есть много ситуаций, где формальные методы не действуют. Например вещество Nitromethane. В справочнике дана его молекулярная формула: CH3NO2, из которой при помощи формальных правил не вывести структурную, где появляются заряды:

O`^-\N$pos(-90)^+/O`/|

Соответственно, и описание SMILES C[N+](=O)[O-] не может быть получено из молекулярной формулы без дополнительной информации о зарядах.

Другой случай связан с функциональной группой {}-SO3H. Проблема в том, что у серы бывают разные валентности. В Синей Книге в таблице 1.3 (P-14.1.2) для серы указано стандартное число связей 2. То есть, формально данная формула раскрывается в {}-S-O-O-O-H. Но на самом деле все предполагают, что должно быть иначе:

{}--S<`||O><||O>-O-H

Это результат общепринятых соглашений. И таких соглашений много.

То есть, традиционные химические формулы в общем случае не предназначены для формализованного описания молекул. Поэтому нужен особый алгоритм, который сможет решать задачу раскрытия различных типов формул в графовое представление.

Для решения выбран Blackboard pattern . Где в роли доски будет выступать система пузырей.

Исходная система строится на основе выражения, полученного при компиляции исходного описания в формате CharChem. Затем различные источники знаний вносят изменения, пока система пузырей не превратится в такой вариант, из которого можно построить граф. Либо в особо тяжких случаях решение может зайти в тупик.

Оновные понятия

Внутренняя валентность — это заданное число. Для водорода - 1, для углерода - 4, и т.п. Изначально обычно не указывается.

Внешняя валентность вычисляется по совокупности факторов — сумма кратностей связей, число присоединённых атомов водорода, заряд.

Свободная валентность — разность между внутренней и внешней.

Сценарии

Самый простой вариант

В простейшем случае узлы исходного описания соответствуют узлам графа, а явно указанные химические связи — рёбрам.

Исходное описание: O=C=O

@:p(c)$bg(#FD8,round,p:1,s:gray){}_(x0.01)$bg(#8F8,round,p:.2,s:gray)&c@; @p(O)_(x%a:1,N0){}_(x%b:.8,N2){}_(x%a,N0)@p(C)_(x%a,N0){}_(x%b,N2){}_(x%a,N0)@p(O)

Тут достаточно одного источника знаний, который определяет, что в пузыре группы находится лишь один пузырь атома. Поэтому валентность атома вычисляется по сумме кратностей связнй. Пузыри групп заменяются на пузыри атомов. После чего система считается решенной.

@:a(c,v)$bg(#8F8,round,p:.2,s:gray)&c(*|0"\scriptsize{V=&v}"*)@; @a(O,2)_(x%a:.55,N0){}_(x%b:.8,N2){}_(x%a,N0)@a(C,4)_(x%a,N0){}_(x%b,N2){}_(x%a,N0)@a(O,2)

Удаление водорода

Для удаления атомов водорода нужен ещё один источник знаний. Возьмём описание формулы H-S-H

@:p(c)$bg(#FD8,round,p:1,s:gray){}_(x0.01)$bg(#8F8,round,p:.2,s:gray)&c@; @:a(c,v)$bg(#8F8,round,p:.2,s:gray)&c(*|0"\scriptsize{&v}"*)@; @p(H)_(x%a:1,N0){}_(x%b:.8){}_(x%a,N0)@p(S:a)_(x%a,N0){}_(x%b){}_(x%a,N0)@p(H) "SingleAtom"--> @a(H,V=1)_(x%a:.55,N0){}_(x%b:.8){}_(x%a,N0)@a(S:b,V=4)_(x%a,N0){}_(x%b){}_(x%a,N0)@a(H,V=1) "HydrogenCollapse"--> @a($C()S,H=2)

Пример: CH3-CH2-OH

Сложные узлы

Если узел не соответствует условиям для вышерассмотренных источников знаний, то это сложный узел. Примеры:

C6H5CO2H
NaHCO3
CH2=CHCH2NCS

Тут для расшифровки понадобится несколько источников знаний.

TemplateGroup

В первую очередь нужно найти шаблонные фрагменты. Здесь это C6H5 и CO3. За это отвечает источник знаний TemplateGroup. Он может найти фрагмент, используя заранее подготовленную таблицу. И если совпадение найдено, то соответствующие атомы удаляются, а вместо них вставляется сформированная группа.

Пример для C2H5OH

@:dn(v)(*_(y0.7,N0)"\scriptsize{&v}"*)@; @:ra(to,p:0.1)$bg(:&to,#8F8,p:&p,round,s:gray)@; @:gb(ref,p:.7)$bg(to:&ref,#FD8,p:&p,r:.6,s:gray)@; @:step(x:1.3)_(x&x,N0)@; C2:a1@step()H5:b1@step()O:c1@step(1)H:d1@gb(a1;d1)@ra(a1)@ra(b1)@ra(c1)@ra(d1) "TemplateGroup "--> $C()C:a2@dn(H=3)_(x1.5)C:b2@dn(H=2)_(x0.8)@step(.6)O:c2@step(1)H:d2@gb(a2;d2,1;.6;1;1)@gb(a2;b2)@ra(a2)@ra(b2)@ra(c2)@ra(d2)

Пример для KHSO4

@:dn(v)(*_(y0.7,N0)"\scriptsize{&v}"*)@; @:ra(to,p:0.1)$bg(:&to,#8F8,p:&p,round,s:gray)@; @:gb(ref,p:.7)$bg(to:&ref,#FD8,p:&p,r:.6,s:gray)@; @:step(x:1)_(x&x,N0)@; K:a1@step()H:b1@step()S:c1@step()O4:d1@gb(a1;d1);@ra(a1)@ra(b1)@ra(c1)@ra(d1) "TemplateGroup "--> $C()K:a2@step()H:b2@step(2)S:c2$slope(45)$L(1.1)(*//O:d2*)(*\\O:e2*)(*`/O:f2_(x%s:-.7)*)(*`\O:g2_(x%s)*)# @gb(a2;d2;e2)@gb(g2;e2,.5)# @ra(a2)@ra(b2)@ra(c2)@ra(d2)@ra(e2)@ra(f2)@ra(g2)

ValencyPredictor

После подстановки шаблонных частей необходимо установить связи между оставшимися атомами. Но для этого необходимо знать их валентность. Точной информации нет. Поэтому придётся делать предположения. Для этого нужен источник знаний ValencyPredictor. Он делает предположения о валентности каждого атома в группе узла. Но прежде сохраняет исходное состояние узла, чтобы его можно было восстановить, если предположения окажутся неверные.

В итоге внешняя валентность должна свопадать с внутренней, а значит свободная = 0.

NodeResolver

Когда валентности расставлены, можно начинать строить правильную структуру. NodeResolver находит узлы по следующим правилам:

  1. Сначала находятся элементы с максимальной свободной валентностью.
  2. Из них нужно выбрать тех, у кого есть сосед с минимальной свободной валентностью.
  3. Исключаются те, у кого сумма соседних freeValency * count превышает из свободную валентность. Нельзя использовать всю свободную валентность, если это не закрывает узел. Например, в CO2 — можно раскрыть связь между углеродом и кислородом. А в HCO2H — нет.
  4. Присоединяющий атом является крайним. (одна неопределённая связь)
  5. Предпочтение отдаётся тем, у кого сосед является крайним.
  6. Возможна ситуация, когда оба кандидата на присоединение не имеют преимущества. Выбирается левый. Но это может быть ошибкой. Поэтому перед этим сохраняется текущее состояние. И если решение заходит в тупик, то состояние восстанавливаетя, после чего выбирается правый.
  7. Выбранный соседний атом присоединяется с кратностью связи = его свободной валентности.

Рассмотрим простой пример H3CCHO. Волнистые линии означают неопределённые связи. Сверху указана свободная валентность.

@:n(n,a:-90,L:.55)<_(A&a,L&L,N0)$itemColor1(gray)"\scriptsize{&n}">@; $L(2)H3-~C@n(4)-~C@n(4)-~H-~O@n(2) "1"--> C@n(1)@n(3H,90)-~C@n(4)-~H-~O@n(2) "2"--> $C()C@n(1)@n(3H,90)-~C@n(3)@n(H,90)-~O@n(2) "3"--> $C()C@n(1)@n(3H,90)-C@n(H,90)@n(2)-~O@n(2) "4"--> C@n(3H,90)-C@n(H,90)=O
  • В начале максимальную свободную валентность имеют два атома углерода. Но первый имеет преимущество, т.к. у него сосед H3, а у второго - просто H.
  • После первого шага три водорода включаются в первый атом углерода. Поэтому его свободная валентность становится 1. Остаётся всего один атом с максимальной свободной валентностью = 4. У него два соседа со свободной валентностью = 1.
  • После второго шага. Второй атом углерода присоединяет водород (у него меньше внутренняя валентность). Свободная валентность второго углерода становится 3. И это всё ещё максимальное значение.
  • На третьем шаге второй углерод (св=3) связывается с первым (св=1) потому второй сосед - кислород имеет св=2. Его св уменьшается до 2.
  • На четвёртом шаге два атома имеют св=2. Но кислород главнее, т.к. он с краю. Хотя в данной ситуации это уже не важно. В результате образуется двойная связь. После чего группа становится решённой, т.к. все свободные валентности = 0 и не осталось неопределённых связей.

Можно поменять местами в исходной формуле последние два атома: H3CCOH. Обычно так делать не принято, т.к. OH обычно используется для гидроксильной группы. Но и не запрещено.

@:n(n,a:-90,L:.55)(*_(A&a,L&L,N0)$itemColor1(gray)"\scriptsize{&n}"*)@; $L(2)H3-~C@n(4)-~C@n(4)-~O@n(2)-~H "1"--> $C()C@n(1)@n(3H,90)-~C@n(4)-~O@n(2)-~H "2"--> $C()C@n(3H,90)-C@n(3)-~O@n(2)-~H "3"--> $C()C@n(3H,90)-C@n(1)<_(y1,N2)O>-~H "4"--> C@n(3H,90)-C@n(H,90)=O

Процесс здесь немного меняется. На втором шаге второй углерод (св=4) связывается с первым (св=1). А на третьем шаге второй углерод связывается с кислородом. Результат такой же, как в предыдущем примере.

CountExplode

Для карбоксильной группы обычно используется описание -COOH. Оно легко решается при помощи NodeResolver. Но бывает и такой вариант: -CO2H. Для его решения понадобится раскрыть O2 -> OO

@:n(n,a:-90,L:.55,c:gray)<_(A&a,L&L,N0)$itemColor1(&c)"\scriptsize{&n}">@; HCO2H -> $L(1.6)$C()H-~C@n(4,c:red)-~O2@n(2)-~H "1"--> $L(2)$C()C@n(3,c:red)@n(H,90)-~$itemColor1(red)O2@n(2)-~H "2"--> C@n(3,c:red)@n(H,90)-~O@n(2)-~O@n(2)-~H "3"--> O=C@n(1)@n(H,90)-~O@n(2,c:red)-~H "4"--> O=C@n(H,90)@n(1)-~O@n(1)@n(H,90) "5"--> O=C@n(H,90)-O@n(H,90)

На втором шаге источник знаний NodeResolver не может выполнить ни одного действия. Потому что атом C с максимальной св=3, не может присоединить два кислорода с суммарной валентностью 4. А расщепление на два отдельных атома даёт возможность успешно завершить решение.

Продолжение по NodeResolver

Достаточно сложный алгоритм работы NodeResolver не гарантирует всегда точного результата. Рассмотрим тяжелый случай: H2CBrCFH2

Конечно, маловероятно что такая формула будет применяться в реальности. Если разделить углеродные узлы горизонтальной связью, то формула станет намного понятнее. Но нам нужен тяжелый случай. 😁

@:n(n,a:-90,L:.55,c:gray)<_(A&a,L&L,N0)$itemColor1(&c)"\scriptsize{&n}">@; @:arr(t)_(x.8,N0)_(x1.2,C)<_(x-.6,y-.5,N0)"&t">_(x.8,N0)@; $L(1.6)$C()H2-~C@n(4,c:green)-~Br@n(1)-~C@n(4)-~F@n(1)-~H2 "1"--> $C()C@n(2)@n(2H,90)-~Br@n(1)-~C@n(4,c:green)-~F@n(1)-~H2@arr(2)# C@n(2)@n(2H,90)-~$color(red)C@n(3,c:green)<_(y1)Br>$color()-~F@n(1)-~H2@arr(3)# $color(red)C@n(2)@n(2H,90,c:red)-~C@n(2)<_(y1.2,x-.4)Br><_(y1.2,x.4)F>-~H2$color()# _(y-.5)_m(y-1)_(x-1)<_(y-.4,N0)"4">_(x-11)_m(x-1)_m(x-1)_(x-.4,y1,C)_(y1,N0)<_(x.5,y.5,N0)"5">_(y1.4,C)_(x-2,y.5,N0)# C@n(2)@n(2H,90)-~Br@n(1)-~C<_(y1)F>@n(3,c:green)-~H2@arr(6)# C@n(2,c:green)@n(2H,90)-~Br@n(1)-~C@n(2H,90)@n(1)-F@arr(7)# Br-C@n(1)@n(2H,90)-~C@n(1)@n(2H,90)-F@arr(8)# Br-C@n(2H,90)-C@n(2H,90)-F

Человеку понятно, что здесь бром относится к первому углероду, а фтор - ко второму. Но после первого шага приоритет получает второй углерод. А два его соседа выглядят равнозначными. На втором шаге принимается ошибочное решение о присоединении брома ко второму углероду. После третьего шага алгоритм заходит в тупик. Поэтому четвёртым шагом приходится вернуть то состояние, которое было до принятия неверного решения. Но теперь второй углерод присоединяет фтор. После чего решение проходит успешно.

Продолжение по ValencyPredictor

Источники знаний

Name Condition Action
SingleAtom Внешний пузырь типа "group" содержит единственный вложенный пузырь типа "atom", count=1. Значение H может быть определено. Замена внешнего пузыря на внутренний. Определение валентности по сумме кратностей внешних связей.
HydrogenCollapse Одиночный атом водорода, связанный ковалентной связью (order=1) с другим атомом (но не водородом). Удаление водородного пузыря. Увеличение значения Н у другого атома.
MononuclearHydride Внутри пузыря группы существуют два вложенных типа "атом". Один из них - водород с произвольным значением count. Другой - не водород, count=1, H не указано. Пузырь водорода удаляется. У оставшегося атома значение Н назначается соответственно count водорода.
